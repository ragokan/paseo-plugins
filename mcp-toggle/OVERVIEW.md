Turns Claude's and Codex's MCP servers on or off. Claude's switches use the per-project list Claude's own `/mcp` command uses (`disabledMcpServers` in `~/.claude.json`). Codex keeps no per-project list, so its switches set `enabled` in `~/.codex/config.toml` and apply to every project.

- **Before a session:** open Manage mcp at the top of the sidebar and pick a project. Its Claude and Codex servers sit side by side; flip them there. New sessions start with that set.
- **During a chat:** the mcp pill above a Claude or Codex agent's composer lists that provider's servers and whether each is enabled. Picking one toggles it and reloads the agent's session so the change takes effect. If the agent was working, the reload stops its turn and the plugin asks it to continue.

Claude settings are per project: a subfolder or a worktree uses its main repository's list, and ZeroSub account homes get the same change. Codex edits go through Codex's own config API (`codex app-server`), which keeps `config.toml`'s comments and layout. A Codex server that a project's `.codex/config.toml` adds or switches shows as locked, since the plugin only edits `~/.codex/config.toml`. Reloading uses the `paseo` command-line tool on the daemon's machine, and Codex changes need the `codex` command-line tool there. Servers from Claude's `.mcp.json` files or from Claude and Codex plugins are not covered.
